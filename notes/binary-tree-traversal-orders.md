# 二叉树遍历：前序、中序、后序

> 前置知识：[二叉树基础](binary-tree-basics.md)  
> 目标：理解遍历名称真正描述的是什么、递归中操作应放在哪个位置，以及何时应选择后序。  
> 关联题目：1372 · Longest ZigZag Path in a Binary Tree、1448 · Count Good Nodes in Binary Tree、437 · Path Sum III

## 1. 一棵树，三种顺序

始终使用同一棵树观察：

```text
        A
       / \
      B   C
     / \   \
    D   E   F
```

每个节点都可以理解为有三个“事件时刻”：

```text
1. 刚到达节点，还没有访问左子树
2. 左子树已经完成，但右子树还没开始
3. 左右子树都已经完成，准备离开节点
```

所谓前序、中序、后序，唯一差别就是：**把“处理当前节点”的动作放在哪个时刻。**

| 遍历 | 固定顺序 | 当前节点何时处理？ | 本例结果 |
| --- | --- | --- | --- |
| 前序（Preorder） | 根 → 左 → 右 | 刚到节点时 | `A B D E C F` |
| 中序（Inorder） | 左 → 根 → 右 | 左子树完成后 | `D B E A C F` |
| 后序（Postorder） | 左 → 右 → 根 | 左右子树完成后 | `D E B F C A` |

“根”指的是当前递归调用中的节点，不一定是整棵树的总根节点。

## 2. 统一的递归骨架

先忽略具体业务，所有深度优先遍历都从这个骨架开始：

```text
dfs(node):
    如果 node 为空：
        返回

    [位置 1：刚到 node]

    dfs(node.left)

    [位置 2：左子树已完成]

    dfs(node.right)

    [位置 3：左右子树均完成]
```

把“访问/打印/计算当前节点”的动作放进不同位置：

```text
前序：位置 1
中序：位置 2
后序：位置 3
```

这比死记 `根左右`、`左根右`、`左右根` 更重要：面对新题时，应根据“什么时候拥有所需信息”来选择操作位置。

## 3. 前序遍历：根 → 左 → 右

```text
dfs(node):
    node 为空时返回

    处理 node                 ← 前序：先处理根
    dfs(node.left)
    dfs(node.right)
```

### 在示例树上的过程

```text
到 A：立刻记录 A
  到 B：立刻记录 B
    到 D：立刻记录 D
    到 E：立刻记录 E
  到 C：立刻记录 C
    到 F：立刻记录 F

结果：A B D E C F
```

### 什么时候用前序？

当前节点的信息需要先传给孩子时，选择前序。例如：

- 从根向下传递路径和、路径最大值或剩余目标；
- 复制/序列化一棵树时先写节点值，再写左右子树；
- 检查根到叶路径；
- 1448 Good Nodes：需要把“祖先路径最大值”传给孩子；
- 437 Path Sum III 的前缀和解法：需要把当前路径前缀和加入状态后，再访问孩子。

思考信号：

```text
当前节点处理后，孩子需要知道我的信息吗？
是 → 往往考虑前序。
```

## 4. 中序遍历：左 → 根 → 右

```text
dfs(node):
    node 为空时返回

    dfs(node.left)
    处理 node                 ← 中序：夹在左右子树之间
    dfs(node.right)
```

### 在示例树上的过程

```text
先一路访问最左：D
回到 B：左子树完成，记录 B
访问 E
回到 A：左子树完成，记录 A
访问 C：其左子树为空，记录 C
访问 F

结果：D B E A C F
```

### 中序最重要的性质：二叉搜索树有序

若一棵树是二叉搜索树（BST）：

```text
左子树所有值 < 当前节点值 < 右子树所有值
```

那么中序遍历会得到递增序列。

```text
      4
     / \
    2   6
   / \ / \
  1  3 5  7

中序：1 2 3 4 5 6 7
```

因此中序常用于：

- 验证一棵树是不是 BST；
- 找 BST 第 `k` 小元素；
- 将 BST 转成有序数组；
- 依次处理“当前值介于左侧与右侧之间”的问题。

### 一个限制

中序遍历是**二叉树特有**的自然概念，因为它要求节点恰好有“左”和“右”两侧。普通多叉树没有唯一合理的“中序”。

思考信号：

```text
题目是 BST，或需要按从小到大访问节点吗？
是 → 优先考虑中序。
```

## 5. 后序遍历：左 → 右 → 根

```text
dfs(node):
    node 为空时返回

    dfs(node.left)
    dfs(node.right)
    处理 node                 ← 后序：孩子都处理完才处理根
```

### 在示例树上的过程

```text
先处理 D
再处理 E
左右孩子都完成后，处理 B
处理 F
左右孩子都完成后，处理 C
最后处理 A

结果：D E B F C A
```

### 什么时候用后序？

当前节点的答案依赖于孩子的答案时，选择后序。

例如：

- 计算树高：先知道左右子树高度，才能算当前高度；
- 判断平衡二叉树：先知道左右子树高度或是否平衡；
- 直径、最大路径和等树形 DP；
- 删除/释放一棵树：先处理孩子，再处理父节点；
- 1372 Longest ZigZag Path：当前节点向左的最佳长度依赖左孩子向右的最佳长度，反之亦然。

对于 ZigZag，可以定义：

```text
left_len(node)  = 从 node 出发，第一步向左的最长 ZigZag 边数
right_len(node) = 从 node 出发，第一步向右的最长 ZigZag 边数
```

递推式是：

```text
left_len(node)  = 1 + right_len(node.left)   （有左孩子时）
right_len(node) = 1 + left_len(node.right)   （有右孩子时）
```

要计算当前节点的 `left_len`，必须先知道左孩子的 `right_len`。所以需要先递归孩子，再处理当前节点，正是后序。

思考信号：

```text
我必须先拿到左右孩子的结果，才能计算当前节点吗？
是 → 往往考虑后序。
```

## 6. 递归调用栈：遍历不是“只往下走”

以这棵树为例：

```text
    A
   / \
  B   C
```

调用顺序会先向下：

```text
dfs(A)
  dfs(B)
    dfs(None)
    dfs(None)
  dfs(C)
    dfs(None)
    dfs(None)
```

但递归函数从孩子返回到父节点时，父节点的函数并没有消失，它会从上次暂停的位置继续执行。

```text
dfs(A) 开始
↓
调用 dfs(B)，A 暂停
↓
dfs(B) 完成并返回
↓
回到 dfs(A) 中 “dfs(left)” 之后的位置
↓
此时才可以执行中序位置的动作，或继续 dfs(A.right)
↓
两个孩子都完成后，才到后序位置
```

因此：

```text
前序：在“递归向下前”做事
中序：在“左边返回后、右边开始前”做事
后序：在“左右都返回后”做事
```

后序并不表示你一开始就从叶子开始调用；调用仍从根开始，只是“处理节点的那一行”会推迟到孩子返回之后。

## 7. Rust 中最小的遍历骨架

LeetCode 二叉树通常是 `Option<Rc<RefCell<TreeNode>>>`。不要先被类型干扰，先定位业务逻辑应该放在哪个位置。

```rust,ignore
fn dfs(node: Option<Rc<RefCell<TreeNode>>>) {
    let Some(node) = node else {
        return;
    };

    let (value, left, right) = {
        let current = node.borrow();
        (current.val, current.left.clone(), current.right.clone())
    };

    // 前序位置：这里可以使用 value，或向孩子传递状态

    dfs(left);

    // 中序位置：左子树已完成，右子树尚未开始

    dfs(right);

    // 后序位置：左右子树均已完成，可组合孩子返回的结果
}
```

实际树形 DP 往往会让 `dfs` 返回值：

```text
dfs(node) -> 当前子树要交给父节点的信息
```

例如：

```text
算树高：返回当前子树高度
算平衡性：返回高度，或返回“不平衡”的特殊状态
算 ZigZag：返回 (下一步向左的长度, 下一步向右的长度)
```

## 8. 迭代遍历的直觉（知道即可）

递归本质上使用了调用栈；迭代遍历则需要自己维护栈。

| 遍历 | 迭代时的关键直觉 |
| --- | --- |
| 前序 | 弹出节点时立刻处理；若栈是后进先出，为先左后右访问，应先压右再压左。 |
| 中序 | 不断把左链压栈；弹出一个节点后处理它，再转去处理它的右子树。 |
| 后序 | 一个节点第一次见到时还不能处理；需要额外记录“左右孩子是否已处理”，或使用两个栈。 |

一开始优先把递归写清楚。只有题目担心递归栈过深、要求显式栈，或需要控制遍历过程时，再改写为迭代。

## 9. 选择顺序的决策表

| 题目需要的信息流 | 优先考虑 | 典型题型 |
| --- | --- | --- |
| 父节点状态要传给孩子 | 前序 | 路径和、祖先最大值、根到叶路径 |
| 需要按 BST 从小到大访问 | 中序 | BST 验证、第 k 小、BST 迭代器 |
| 孩子结果要汇总到父节点 | 后序 | 树高、平衡性、直径、树形 DP、ZigZag |
| 按层处理节点 | 层序（BFS） | 最小深度、右视图、层平均值 |
