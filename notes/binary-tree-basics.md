# 二叉树基础

> 目标：重新建立二叉树的结构直觉、术语、性质、表示方式与常见解题入口。  
> 延伸阅读：[二叉树遍历：前序、中序、后序](binary-tree-traversal-orders.md)

## 1. 什么是二叉树？

二叉树（binary tree）是一种树结构：每个节点最多有两个孩子，并且两个位置有明确区别：

```text
左孩子（left child）
右孩子（right child）
```

“最多两个”意味着一个节点可能有：

```text
0 个孩子：叶子节点
1 个孩子：只有左孩子，或只有右孩子
2 个孩子：同时有左右孩子
```

左右位置不能互换。下面两棵树不是同一棵二叉树：

```text
  1          1
 /            \
2              2
```

即使节点值相同，左、右边的结构也不同。

## 2. 必会术语

用这棵树统一说明：

```text
          1                 ← 根节点（root）
        /   \
       2     3
      / \     \
     4   5     6
```

| 术语 | 含义 | 示例 |
| --- | --- | --- |
| 根节点（root） | 整棵树最上方、没有父节点的节点 | `1` |
| 父节点（parent） | 直接连向下一层节点的节点 | `2` 是 `4` 的父节点 |
| 孩子节点（child） | 直接由某个父节点连出的节点 | `4` 是 `2` 的孩子 |
| 左/右孩子 | 孩子所在的明确方向 | `2` 是 `1` 的左孩子；`3` 是右孩子 |
| 兄弟节点（sibling） | 同一个父节点的两个孩子 | `2` 与 `3`；`4` 与 `5` |
| 叶子节点（leaf） | 没有任何孩子的节点 | `4`、`5`、`6` |
| 内部节点（internal node） | 至少有一个孩子的节点 | `1`、`2`、`3` |
| 子树（subtree） | 某节点及其全部后代组成的树 | `2` 为根的子树是 `2,4,5` |
| 祖先（ancestor） | 从根到节点路径上的上方节点 | `1`、`2` 是 `5` 的祖先 |
| 后代（descendant） | 某节点下面的任意节点 | `4`、`5` 是 `2` 的后代 |
| 边（edge） | 父子节点之间的连线 | `1 → 2` |

任何一棵有 `n` 个节点、且 `n > 0` 的树，必定有：

```text
n - 1 条边
```

因为除根节点外，每个节点恰好有一条来自父节点的边。

## 3. 深度、层数与高度：先统一“按边还是按节点”

这是树题最常见的 off-by-one 来源。每次都要先看题目到底按**边数**还是按**节点数**定义长度。

### 深度（depth）

节点深度通常指：从根到该节点经过的边数。

```text
          1       depth = 0
        /   \
       2     3     depth = 1
      / \     \
     4   5     6   depth = 2
```

有的资料称根为第 `1` 层；有的称根为第 `0` 层。两种都可以，但同一题中必须保持一致。

### 高度（height）

节点高度通常指：从该节点向下到最深叶子经过的最长边数。

```text
          1       height = 2
        /   \
       2     3     height = 1
      / \     \
     4   5     6   height = 0
```

因此：

```text
树的高度 = 根节点的高度
```

### 题目中可能按“节点数”计高度

例如 LeetCode 的 `Maximum Depth of Binary Tree` 通常将：

```text
单节点树深度定义为 1
空树深度定义为 0
```

这相当于按路径上的节点数计，而不是边数。

而 `Longest ZigZag Path` 计算的是边数：

```text
单节点路径长度 = 0
```

遇到长度题，先问：

```text
路径长度按边算，还是按节点算？
空树、单节点的答案分别是什么？
```

## 4. 常见二叉树类型

### 普通二叉树

只要求每个节点最多有两个孩子；没有其他结构限制。

### 满二叉树（full / strict binary tree）

每个节点要么没有孩子，要么恰好有两个孩子；不存在“只有一个孩子”的节点。

```text
      1
     / \
    2   3
       / \
      4   5
```

上图是满二叉树，即使每层没有填满。

若满二叉树有 `i` 个内部节点，则叶子数为：

```text
leaves = i + 1
```

这个公式只适用于“每个内部节点恰好有两个孩子”的满二叉树。

### 完美二叉树（perfect binary tree）

同时满足：

- 所有内部节点都有两个孩子；
- 所有叶子都在同一层。

若根深度为 `0`、树高为 `h`（按边计），则：

```text
第 d 层节点数：2^d
叶子节点数：2^h
总节点数：2^(h + 1) - 1
```

```text
        1
      /   \
     2     3
    / \   / \
   4  5  6  7
```

### 完全二叉树（complete binary tree）

除最后一层外，每一层都填满；最后一层的节点从左到右连续排列，不能出现空洞。

```text
        1
      /   \
     2     3
    / \   /
   4  5  6
```

这是完全二叉树。下面不是，因为最后一层出现了左侧空位：

```text
        1
      /   \
     2     3
          /
         6
```

堆（heap）通常使用完全二叉树，因此非常适合数组表示。

### 平衡二叉树（balanced binary tree）

“平衡”在不同资料中可能有不同严格定义。算法题中常见含义是：

```text
任意节点的左右子树高度差不超过 1
```

它关注的是树不要退化得过深，以避免操作从 `O(log n)` 恶化到 `O(n)`。

### 倾斜/退化树（skewed / degenerate tree）

每个节点都只有一个孩子时，二叉树退化成链表：

```text
1
 \
  2
   \
    3
     \
      4
```

此时树高为 `n - 1`，递归 DFS 的调用栈也可能达到 `O(n)`。

### 二叉搜索树（BST）

对每个节点都满足：

```text
左子树所有值 < 当前节点值 < 右子树所有值
```

注意是“整棵左右子树”，不是只比较直接孩子。

例如：

```text
      5
     / \
    3   7
   / \ / \
  2  4 6  8
```

BST 的中序遍历是有序的。普通二叉树并不具备这个性质。

重复值放在哪一侧取决于题目定义：有些题允许左 `<=`、右 `>`，有些允许相反规则，不能自行假设。

## 5. 二叉树的两种常见表示

### 指针/链接表示：最适合递归

概念上每个节点保存：

```text
value
left child
right child
```

```text
TreeNode
├── val
├── left: Option<...>
└── right: Option<...>
```

这是 LeetCode 二叉树题常见形式。孩子为 `None` 表示不存在。

自己设计普通树时，常用：

```text
Option<Box<TreeNode>>
```

LeetCode Rust 常提供：

```text
Option<Rc<RefCell<TreeNode>>>
```

它们在树形算法中的逻辑相同：先处理空节点，再读取当前值、左孩子、右孩子。关于 Rust 类型细节，见：[Rust：`Rc`、`Arc` 与 `RefCell`](rust-smart-pointers-and-interior-mutability.md)。

### 数组表示：最适合完全二叉树

如果根节点下标是 `0`，某节点下标是 `i`：

```text
左孩子下标：2 * i + 1
右孩子下标：2 * i + 2
父节点下标：(i - 1) / 2
```

这是堆的基础。

数组表示适合完全二叉树，因为节点位置连续；普通稀疏树若硬用数组，会浪费很多空位。

LeetCode 常用层序数组来描述树，例如：

```text
[1, 2, 3, null, 4]
```

表示：

```text
    1
   / \
  2   3
   \
    4
```

这里的 `null` 不是一个节点，而是“对应位置没有左孩子”。

## 6. 两种基本走法：DFS 与 BFS

### 深度优先搜索（DFS）

DFS 会先沿某一条分支尽量向下，再回溯处理其他分支。递归写法天然就是 DFS。

```text
dfs(node):
    node 为空时返回
    处理当前节点 / 传递状态 / 获取孩子结果
    dfs(left)
    dfs(right)
```

前序、中序、后序都是 DFS，只是处理当前节点的时机不同。详见：[二叉树遍历：前序、中序、后序](binary-tree-traversal-orders.md)。

适合：

- 根到叶路径；
- 子树递归结果；
- 树形 DP；
- 判断结构、计算高度、路径和、祖先约束。

### 广度优先搜索（BFS / 层序遍历）

BFS 按层访问节点，需要一个队列：

```text
第 0 层：根
第 1 层：根的孩子
第 2 层：下一层孩子
...
```

适合：

- 按层输出节点；
- 求最小深度；
- 每层平均值、最大值、右视图；
- 判断完全二叉树；
- 找离根最近的满足条件节点。

DFS 与 BFS 都能访问每个节点一次，时间通常都是 `O(n)`；差别在状态组织与额外空间：

```text
DFS：递归栈 / 显式栈，最坏 O(h)
BFS：队列，最坏可能 O(n)
```

## 7. 两类递归思维：自上而下与自下而上

这是做树题最实用的分类。

### 自上而下（top-down）

父节点先做决定或维护状态，再把状态传给孩子。

```text
dfs(node, 从根传下来的状态)
```

典型状态：

```text
路径和
路径最大值/最小值
剩余目标值
当前深度
当前路径
```

例子：

- 1448 Good Nodes：传递当前路径最大值；
- 路径和题：传递累计和或剩余值；
- 437 Path Sum III 前缀和：传递当前前缀和与路径哈希表。

这通常对应前序位置，因为状态必须在进入孩子前更新。

### 自下而上（bottom-up）

先从左右孩子得到结果，再计算当前节点的结果。

```text
dfs(node) -> 交给父节点的信息
```

典型返回值：

```text
子树高度
子树节点数
是否平衡
最大路径贡献
多个方向状态的元组
```

例子：

- 求树高：`1 + max(left_height, right_height)`；
- 判断平衡树：先得到左右高度；
- 1372 ZigZag：返回 `(left_len, right_len)`。

这通常对应后序位置，因为必须先等孩子结果返回。

## 8. 树题的通用检查清单

写题前先回答：

1. 空树的答案是什么？
2. 单节点树的答案是什么？
3. 长度按边数还是按节点数？
4. 路径是否必须从根开始、到叶子结束、只能向下？
5. 题目需要父节点向下传状态，还是孩子向上返回结果？
6. 是否是 BST、完全二叉树或其他有额外性质的树？
7. 节点值会不会重复、为负、或造成路径和溢出？
8. 树可能退化成链表吗？递归深度是否需要注意？

## 9. 推荐学习顺序

先建立小题的肌肉记忆，再做路径与树形 DP：

```text
1. 二叉树最大深度
2. 相同的树 / 对称二叉树
3. 翻转二叉树
4. 二叉树的前、中、后序与层序遍历
5. 路径总和（根到叶）
6. Good Nodes / Path Sum III（路径状态）
7. 平衡二叉树 / 直径（孩子结果向上汇总）
8. Longest ZigZag Path（树形 DP 的方向状态）
9. BST：验证、搜索、第 k 小、最近公共祖先
```

学习时优先问“递归函数的含义是什么”，再考虑 Rust 的 `Option`、`Rc`、`RefCell` 语法。
