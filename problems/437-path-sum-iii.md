## 1. 我自己的题意

给定一棵二叉树和目标值，统计所有“从某个节点开始、只沿父节点到子节点方向向下”的路径，使路径上的节点值之和等于目标值。路径不要求从根开始，也不要求在叶子节点结束。

## 2. 手算例子

使用 LeetCode 示例树：

```text
          10
        /    \
       5     -3
     /   \     \
    3     2     11
   / \     \
  3  -2     1
```

目标值为 `8` 时，完整示例树中共有三条合法路径：

- `5 → 3`
- `5 → 2 → 1`
- `-3 → 11`

目标值可以是 `0`，节点值也可以为负数，因此不能只使用单调性或滑动窗口。

## 3. 不看提示的思考

最直接的方法是把每个节点都当作路径起点，再向下 DFS 统计路径和。这个方法能覆盖所有路径，但在退化树上会重复遍历大量节点，最坏复杂度为 `O(n²)`。

需要把“所有起点”合并到一次 DFS 中。对于当前根到节点的路径，若当前前缀和为 `current_sum`，之前某个祖先位置的前缀和为 `current_sum - target_sum`，那么从该位置之后到当前节点的路径就满足目标和。

## 4. 最终思路

### 核心观察

设从根到当前节点的前缀和为 `S`。若路径上存在更早的前缀和 `P`，满足：

```text
S - P = target_sum
```

则 `P = S - target_sum`，并且每出现一次这样的 `P`，就对应一条以当前节点结尾的合法向下路径。

### 状态定义 / 不变量

`prefix_sums[p]` 表示当前 DFS 路径上，前缀和 `p` 出现的次数。

进入节点时，哈希表只包含根到其父节点路径的前缀和；加入当前节点后，它包含根到当前节点的路径。离开节点前撤销当前前缀和，保证回溯到兄弟子树时状态不受影响。

初始放入：

```text
prefix_sums[0] = 1
```

它代表空路径，能够正确统计从根开始的路径。

### 步骤

1. 计算当前前缀和 `current_sum`。
2. 查询 `current_sum - target_sum` 出现的次数，作为以当前节点结尾的路径数量。
3. 将 `current_sum` 加入哈希表。
4. 递归处理左右子树。
5. 回溯时移除当前 `current_sum`，再返回结果。

## 5. 为什么正确

对任意当前节点，根到当前节点的路径和为 `S`。任意一条以当前节点结尾的向下路径，都唯一对应一个更早的前缀位置，其前缀和为 `S - target_sum`。因此哈希表查询会完整统计所有以当前节点结束的合法路径，且不会重复。

DFS 会访问每个节点一次。当前节点处理结束后撤销自己的前缀和，所以每个子树只使用从根到该子树根的真实路径状态，不会把不同分支拼成非法路径。

## 6. 复杂度

- 时间：`O(n)`，每个节点进行常数次哈希表操作。
- 空间：`O(h)`，哈希表和递归栈最多保存当前路径的信息；`h` 为树高。

## 7. 实现前检查清单

- [x] 空树返回 `0`。
- [x] 目标值为 `0` 时，初始前缀和 `0` 必须存在。
- [x] 允许负数节点值。
- [x] 同一前缀和可能出现多次，必须保存出现次数。
- [x] 递归返回前必须回滚当前前缀和。
- [x] 使用 `i64` 保存前缀和，避免路径累加溢出。

## 8. 复盘

- 真正学到的模式：树上任意起点的路径和，可以转化为 DFS 路径上的前缀和差值。
- 下次看到的信号：路径不要求从根开始，但要求连续向下，且目标是路径和。
- 容易犯的错误：只统计根路径；忘记保留重复前缀和；递归后不回滚状态。
- 与朴素解法的关系：朴素解法适合先验证题意；前缀和哈希表把重复的起点搜索合并成一次遍历。
