## 1. 我自己的题意

从根到任意节点的路径上，若该节点的值不小于它所有祖先节点的值，则它是 Good Node。根节点没有祖先，因此一定是 Good Node。要求统计整棵树中 Good Node 的数量。

## 2. 手算例子

```text
    5
   /
  3
 /
5
```

- 根 `5`：Good Node。
- 中间 `3`：路径上已有 `5`，`3 < 5`，不是 Good Node。
- 最下面 `5`：路径最大值是 `5`，`5 >= 5`，是 Good Node。

答案是 `2`。

这个例子确认了两个边界：比较必须包含所有祖先，而不是只比较父节点；相等时也算 Good Node。

## 3. 不看提示的思考

从根向下走时，记住当前路径上的最大值。对于当前节点值 `x`：

- 如果 `x >= max_so_far`，当前节点是 Good Node。
- 无论它是否为 Good Node，继续访问孩子时都应传递 `max(x, max_so_far)`。

因此每个递归调用不只需要当前节点，也需要一条从根传下来的路径状态：`max_so_far`。

## 4. 递归定义

`dfs(node, path_max)` 返回：**以 `node` 为根的整棵子树中 Good Node 的总数**；`path_max` 是从根到 `node` 的父节点为止的路径最大值。

### 基线条件

若当前节点为空，子树没有节点，返回 `0`。

### 当前层的贡献

- 当前节点值 `x >= path_max` 时，贡献 `1`。
- 否则贡献 `0`。

设 `next_max = max(path_max, x)`，递归结果为：

```text
当前节点的贡献
+ 左子树的 Good Node 数量（使用 next_max）
+ 右子树的 Good Node 数量（使用 next_max）
```

初始调用将路径最大值设为 `i32::MIN`。这让根节点直接走同一条判断逻辑，无须特殊计数；也可以从根值开始，但那样需要把根节点单独计入。

## 5. 为什么正确

对每个节点，`path_max` 精确保存了从根到其父节点路径上的最大值。因此当前判断 `x >= path_max` 与 Good Node 的定义完全等价。

更新为 `next_max = max(path_max, x)` 后，传给每个孩子的状态又恰好是从根到当前节点路径上的最大值。递归会遍历每个节点一次，分别计算左右子树并相加，所以既不会遗漏节点，也不会重复计数。

## 6. 复杂度

- 时间：`O(n)`，每个节点只访问一次。
- 空间：`O(h)`，递归调用栈的深度为树高；最坏退化为链表时是 `O(n)`。

## 7. 实现前检查清单

- [x] 空树应返回 `0`。
- [x] 根节点应自动被计为 Good Node。
- [x] 相等值使用 `>=`，不是 `>`。
- [x] 与整条祖先路径的最大值比较，不能只和父节点比较。
- [x] 空间复杂度应按递归深度而非节点总数描述。
